# Google OAuth project + scope isolation for YouTube automation

Session lesson: when a user says to keep the project as Hermes/HeRmEz, distinguish the **Google Cloud OAuth project/app** from local repo/project names.

## Key rules

- The OAuth consent app shown to the user is controlled by the `client_id` / `project_id` in the active `*_client_secret.json`, not by the local folder name.
- If Google shows `Access blocked` / `Error 403: access_denied` for a test user, check that the auth URL's `client_id` belongs to the Google Cloud project where the user added test users.
- Do not assume adding a test user in one Google Cloud project fixes OAuth URLs generated from another project's client secret.
- Keep Workspace/Gmail and YouTube OAuth tokens separate even when the account email is the same:
  - Workspace token: Gmail/Calendar/Drive/Docs/Sheets/Contacts scopes; used for source email processing and admin workflows.
  - YouTube token: `youtube.upload`, `youtube.force-ssl`, `youtube.readonly`, `yt-analytics.readonly`; used for channel upload/edit/analytics.
- When the user asks to preserve “old scopes” while adding YouTube, regenerate/provide both flows separately instead of mixing all permissions into one unclear token.

## Verification steps

1. Inspect the client secret used for the OAuth URL:
   - `project_id`
   - `client_id`
   - `redirect_uris`
2. Compare it to the Google Cloud project open in the user's screenshot / console.
3. If migrating to the Hermes OAuth project, replace YouTube client secrets with a client created under the Hermes Google Cloud project that has the correct redirect URI and YouTube API enabled.
4. Regenerate fresh auth URLs after replacing client secrets; old URLs contain old `state`, `code_challenge`, and `client_id`.
5. After callback exchange, verify the YouTube channel ID and store it in the profile registry before using it as a failover channel.

## Pitfalls

- Google Cloud project IDs cannot be renamed after creation; the practical fix is to create/use the correct OAuth client under the desired project and update local client-secret files.
- A Workspace OAuth client can only be reused for YouTube if it is intentionally configured for the YouTube scopes/API and the redirect URI generated by the tool. Otherwise create/download a dedicated OAuth client under the same Google Cloud project.
- Do not mark a pending failover account active until it has a saved token and verified channel ID.
