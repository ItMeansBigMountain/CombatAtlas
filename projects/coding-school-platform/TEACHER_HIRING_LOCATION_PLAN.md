# Teacher Hiring and Location Assignment Plan

- **Project:** Coding School Platform
- **Created:** 2026-05-03
- **Runner:** Heartbeat
- **Goal:** Define teacher roles and a simple location assignment workflow without performing hiring, legal, payroll, or public posting actions.

## Legal / business dependency

Actual hiring should wait until the business foundation is ready.

Manual prerequisites before real hiring:

- LLC/entity decision completed.
- Brand/trademark direction reviewed.
- Contractor vs employee classification reviewed.
- Pay rate and payment method approved.
- Background check / child-safety process selected if teachers work with minors.
- Parent/student liability, media release, and code-of-conduct policies drafted and reviewed.
- Public job posting approved by Affan.

This document is only an operating plan. It is not a hiring action.

## Role 1: Scratch Teacher

### Purpose

Teach beginner students programming fundamentals through visual projects, games, animations, and stories.

### Ideal profile

- Comfortable teaching children patiently.
- Can explain loops, events, variables, conditionals, broadcasts, and sprites visually.
- Can guide students without overbuilding the project for them.
- Can keep lessons energetic and structured.

### Core responsibilities

- Teach Scratch basics through 45-60 minute lessons.
- Help students build small projects each session.
- Track student progress after each class.
- Assign simple practice tasks.
- Escalate parent/student issues to Affan/operator.

### Sample trial lesson

Build a simple maze game:

- Move sprite with arrow keys.
- Detect wall collision.
- Add goal sprite.
- Add win message.
- Optional: timer or score.

### Screening task

Candidate records or delivers a 10-minute mini-lesson explaining Scratch events and loops to a 9-year-old beginner.

## Role 2: Python Teacher

### Purpose

Teach beginner-to-intermediate students text-based programming with practical projects.

### Ideal profile

- Strong Python fundamentals.
- Can teach variables, conditionals, loops, functions, lists, dictionaries, files, and simple APIs.
- Can debug calmly with beginners.
- Understands how to scaffold projects instead of lecturing only.

### Core responsibilities

- Teach Python fundamentals through small projects.
- Review student code and explain errors.
- Maintain lesson notes and progress tracking.
- Assign practice problems or mini-projects.
- Recommend when students are ready for advanced topics.

### Sample trial lesson

Build a number guessing game:

- Generate secret number.
- Ask for user input.
- Compare guesses with `if` statements.
- Use a loop for repeated guesses.
- Count attempts.

### Screening task

Candidate records or delivers a 10-minute mini-lesson explaining `if` statements and loops using the number guessing game.

## Shared teacher expectations

- Be patient, clear, and encouraging.
- Use age-appropriate explanations.
- Keep lessons project-based.
- Do not shame students for mistakes.
- Avoid discussing politics, religion, or adult topics in class.
- Keep parent communication professional.
- Never share student personal information outside approved systems.
- Follow child-safety and privacy rules once finalized.

## Location assignment workflow

### Location model

Use a simple three-layer model:

1. **Region** - city/metro area, e.g. Dallas-Fort Worth.
2. **Location** - library, community center, partner site, home/virtual, or school.
3. **Class slot** - day/time/level/teacher assignment.

### Assignment steps

1. Collect candidate teacher availability.
2. Tag teacher by skill:
   - Scratch
   - Python
   - both
   - beginner-friendly
   - advanced-capable
3. Tag teacher by region and travel radius.
4. Match teacher to location based on:
   - subject need
   - student level
   - travel radius
   - availability
   - class size
   - safety/compliance readiness
5. Assign one primary teacher and one backup if possible.
6. Confirm assignment manually before communicating publicly.
7. Record assignment in a simple tracker.

## Location assignment tracker fields

Use these columns in a future spreadsheet/app:

| Field | Purpose |
|---|---|
| Teacher name | Assignment identity |
| Role | Scratch / Python / both |
| Region | Metro/city area |
| Location name | Teaching site |
| Location type | virtual, library, community center, school, home, partner |
| Travel radius | Maximum commute |
| Availability | Days/times |
| Class level | beginner, intermediate, advanced |
| Class size max | Capacity planning |
| Background check status | Manual compliance field |
| Contract status | Manual legal/admin field |
| Assigned classes | Active class slots |
| Backup teacher | Coverage plan |
| Notes | Issues/preferences |

## First safe operating tasks

1. Draft public-facing teacher role descriptions, but do not post yet.
2. Create a spreadsheet/template using the tracker fields above.
3. Draft a 10-minute screening rubric for Scratch and Python trial lessons.

## Manual / approval-sensitive actions

Do not automate without Affan approval:

- Posting jobs publicly.
- Contacting candidates.
- Running background checks.
- Signing contracts.
- Paying teachers.
- Assigning teachers to real students.
- Collecting student/parent personal data.
- Publishing class schedules or location details.

## Recommendation

Start with one Scratch teacher and one Python teacher pilot. Keep the first class format simple, local/virtual, and project-based. Do not expand locations until one class loop is validated end-to-end.
